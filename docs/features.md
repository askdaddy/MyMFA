# 功能规格

> 关联决策：[ADR-003 预提示](decisions.md#adr-003)、[ADR-004 令牌范围](decisions.md#adr-004)、[ADR-008 图标](decisions.md#adr-008)、[ADR-010 时钟校准](decisions.md#adr-010)
> 状态：设计基线，尚未实现

## 1. 列表与预提示

### 1.1 条目行布局

```
┌────────────────────────────────────────────┐
│ ┌──┐  GitHub                        [工作] │
│ │G │  alice@example.com                     │
│ └──┘                                       │
│        654 321        ⏱ 00:23              │
│        next 987 654        ← 小字、灰色     │
└────────────────────────────────────────────┘
```

- **首字母色块**：取 `issuer` 首字符（非 ASCII 时取首个可见字符），大写显示。背景色由 `issuer` 字符串哈希映射到固定色板，保证同一服务商在任何设备上颜色一致。见 §6。
- **当前码**：主区域大字号，按 3 位分组显示（`654 321`），便于口述与快速阅读。
- **倒计时**：环形进度条 + 剩余秒数。
- **预提示码**：当前码正下方，小字号、灰色/降低对比度，始终可见（无需点击）。

### 1.2 预提示语义（核心差异点）

预提示显示的是**紧接当前周期之后的那一个周期的验证码**。

| 令牌类型 | 预提示内容 | UI 标注 |
|---|---|---|
| TOTP | `period` 步长 +1 计算出的码 | `next` 或"下一周期" |
| HOTP | `counter + 1` 计算出的码 | **必须**标注为"下一计数器"，与时间无关 |

HOTP 的标注区分是强制要求：HOTP 的 `counter+1` 码不会因时间流逝而失效，用户若误以为它像 TOTP 一样"30 秒后就变了"，会在错误的时机使用它。

**为什么始终可见而非点击展开**：用户在需求确认中明确选择了这个形态。它牺牲了一部分防窥视能力，换取"提前复制、无需额外交互"的效率——部分服务只接受下一个时间窗的码，或用户需要在码切换前就粘贴出去。

**开关**：`settings.previewNextCode` 可全局关闭，关闭后列表只显示当前码。

### 1.3 性能约束

- 每个可见行每个 tick 需要 2 次 HMAC 计算（当前码 + 下一码）
- 200 条目全量计算约 400 次 HMAC / 30 秒，性能可接受
- **但必须配合列表虚拟化**，只对可视区域内的行计算，滚动时按需计算
- 倒计时进度条用 1 秒间隔刷新，验证码本身在周期边界刷新，不需要每秒重算 HMAC
- 周期边界刷新要在**所有行同一时刻**触发，避免各行倒计时不同步造成的视觉跳动

### 1.4 时钟校准

TOTP 完全依赖系统时间。用户手机时间偏差 30 秒会导致全部验证码失效，且用户很难自行诊断出是时钟问题（只会觉得"这个 App 的码是错的"）。

功能设计：

- 设置项提供「与服务端时间校准」按钮
- 通过请求任一可信 HTTPS 端点，读取响应头 `Date`，与本地时间求差得到 `clockOffsetSeconds`
- 该偏移量存入 vault settings，生成 TOTP 时补偿
- 偏差绝对值 > 5 秒时，列表顶部显示常驻提示条，引导用户校准
- 校准是**本地补偿**，不修改系统时间（无权限，也不应越权）

端点选择需注意：不能依赖单一服务，建议内置 2–3 个候选并做失败回退。此项待 M6 确认具体端点。

## 2. 条目管理

### 2.1 新增

- **扫码添加**：相机扫描 `otpauth://` 二维码，解析后进入确认页
- **手动添加**：表单填写 issuer / account / secret（base32）/ 类型 / 算法 / 位数 / 周期
- **从图片识别二维码**（移动端）：相册选图解析，Android/iOS 均有原生能力
- secret 输入框需实时校验 base32 合法性，并容忍缺失 padding、空格与 `0/O`、`1/I` 混淆字符
- 手动输入时提供"显示当前码"实时预览，便于用户确认 secret 输对了

### 2.2 编辑

可编辑全部字段。修改 `secret` 需二次确认（改错会导致验证码永久失效）。

### 2.3 删除

二次确认。删除后依赖自动备份兜底（见 [vault-format.md §6](vault-format.md#6-自动备份)）。是否需要回收站为待确认项。

### 2.4 使用计数

`usageCount` 递增与 `lastUsedAt` 更新的触发时机：**用户主动复制验证码**或**点击条目展开**时。仅仅是条目在列表中可见**不计入**，否则排序会被列表滚动位置污染。

## 3. 排序

| 排序方式 | 键 | 方向 |
|---|---|---|
| 手动 | `position`（fractional index） | 拖拽决定 |
| 服务商 | `issuer` | 升/降 |
| 账户名 | `account` | 升/降 |
| 使用次数 | `usageCount` | 降序为主 |
| 最近使用 | `lastUsedAt` | 降序为主 |
| 创建时间 | `createdAt` | 升/降 |

**稳定排序规则**：无论选择哪种主排序，二级排序键恒为 `issuer + account`。这保证排序结果稳定、不随时间抖动——否则使用次数相同的条目会在每次刷新时随机换位，用户找不到东西。

`favorite` 条目恒置于最前，独立于排序方式。

手动排序的拖拽只在 `defaultSort === "manual"` 时可用；其他排序方式下拖拽需提示"切换到手动排序"。

## 4. 搜索

- 匹配范围：`issuer`、`account`、`note`、tag 名
- 算法：子序列（subsequence）模糊匹配 + 评分排序，自行实现打分逻辑，不引重型模糊搜索库
- 评分倾向：完全前缀匹配 > 词首匹配 > 子序列匹配；短字段命中权重更高
- **拼音首字母匹配**（`settings.searchPinyin`）：中文条目可用拼音首字母搜索（如"支付宝"→ `zfb`）。拼音表会增加包体积，做成按需加载
- 搜索态下仍显示预提示码，且倒计时照常运行
- 搜索框支持快捷清空；无结果时提供"创建新条目并预填搜索词"入口
- 搜索**不匹配 secret**，这是刻意的——避免用户在搜索框里粘贴密钥

## 5. Tag 与备注

### 5.1 Tag

- 全局实体（id / name / color / position），条目通过 `tagIds` 引用
- 支持多标签，标签栏可横向滚动 + 多选筛选
- 标签管理界面：重命名、改色、删除、拖拽排序
- 删除标签时提示影响条目数，只解除关联不删条目
- 标签名在 vault 内唯一，大小写不敏感去重
- 筛选与搜索可叠加（先按标签筛，再在结果内搜索）

### 5.2 备注

- 自由文本，多行
- 列表态不显示备注内容，仅在有备注时显示一个小标记（避免泄露敏感信息到列表视图）
- 纯文本，**不渲染 HTML/Markdown**（当前设计），避免富文本带来的 XSS 与渲染安全面

## 6. 图标方案

按用户决策：**不做服务商图标，只用首字母色块**。

- 色板：预设 12–16 个低饱和度、深浅一致的颜色，确保在浅色与深色主题下都有足够对比度
- 映射：`hash(issuer) % 色板长度`，哈希函数需稳定且跨端一致（用简单的 FNV-1a 之类，不用带随机种子的哈希）
- 回退：`issuer` 为空时用 `account` 首字符
- 首字符提取需正确处理 Unicode（用 `Array.from(str)[0]` 而非 `str[0]`，避免 emoji / 代理对 / 组合字符被截断成乱码）

**这个决策的取舍**：牺牲了视觉识别度（Aegis 有真图标），换来零依赖、零许可证风险、零包体积、零图片加载性能问题。若未来要加图标，架构上只需在 Entry 增加可选 `icon` 字段并做回退，不破坏现有 vault。

## 7. 安全相关的 UI 要求

| 项 | 要求 |
|---|---|
| 解锁页 | 主密码输入 + 生物识别快捷入口；错误提示不泄露"密码错"还是"文件坏" |
| 创建 vault | 强制设置主密码；提供强度指示；明确告知**无法找回**，没有后门 |
| 明文导出 | 显著风险警告 + 二次确认 + 不默认选中 |
| 自动锁定 | `autoLockSeconds` 空闲后回到解锁页 |
| 防截屏 | Android `FLAG_SECURE` / iOS 截屏遮罩，设置项开关 |
| 最近任务卡片 | 进入后台时覆盖遮罩 |
| 剪贴板 | 复制验证码后按 `clipboardClearSeconds` 自动清空 |
| 主密码修改 | 要求输入旧密码；只需重新包裹 DEK，无需重加密全库 |

## 8. 通用体验要求

- 深色模式跟随系统，并支持强制指定
- 无障碍：验证码需可被读屏软件朗读（但预提示码应标注为次要信息，避免读屏把两个码连读造成混淆）；所有可点击元素有最小触控尺寸与语义标签
- 空状态引导：无条目时展示"扫码添加 / 手动添加 / 导入备份"三个入口
- 首次启动引导：说明本地优先、无云同步、主密码不可找回
- 国际化：中英双语起步，文案外置不硬编码
